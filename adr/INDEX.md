# SPP Prerequisite & Architecture Decision Records (`adr/INDEX.md`)

This directory is the canonical source of truth for all prerequisite and cross-cutting Architecture Decision Records (ADRs) for the **Self-Service Provisioning Platform (SPP)**, consumed as the sole input by the **AI Software Factory** ([`vaishnavi4068/spp-factory-foundation`](https://github.com/vaishnavi4068/spp-factory-foundation)).

See **[`../docs/source-provenance.md`](../docs/source-provenance.md)** for the provenance of the four-gate data model (`specs/data-model/spp_state_model.sql`), naming specification (`specs/naming/naming-spec.json`), GCS bucket walkthrough (`specs/examples/gcs_bucket.gates.json`), Spanner walkthrough (`specs/examples/spanner.gates.json`), applied user overrides, and unverified source gaps.

---

## 1. Five-Level ADR Hierarchy (Aligned with `spp-factory-foundation`)

| Level | Folder | ID Prefix | Scope |
| :--- | :--- | :--- | :--- |
| **1. Global** | `adr/global/` | `ADR-GLB-` | Platform-wide invariants: global architecture overview, languages & stack, four-gate state model (`Requested -> Approved -> Expected -> Observed`), 18-table `idp` data model on AlloyDB for PostgreSQL, Workload Identity & auth, naming conventions (`nonprod`/`prod`), governance gates/guardrails/invariants (`INV-1..INV-9`), canonical label standard (`LBL-001`/`LBL-002`), and resource kind registry (`idp.resource_kind`) |
| **2. Business Process** | `adr/business-process/` | `ADR-BP-` | Stakeholder ownership map, Operations governance, persona permissions, sequential approval gates (`gcs_bucket_owner`, `spanner_data_owner`, SLA/escalation, self-approval denial, human approval for all deletes), and 6-phase product build order |
| **3. Endpoint / Service** | `adr/endpoint-service/` | `ADR-SVC-` | Cross-cutting vertical slice and endpoint service specifications: `gcs_bucket` (`ADR-SVC-001`, `GCS-*` guardrails) and `spanner_instance` / `spanner_database` (`ADR-SVC-002`, `SPN-*` guardrails, 5 Spanner quirks) |
| **4. Per Cloud** | `adr/per-cloud/gcp/` | `ADR-CLD-GCP-` | Runtime platform on GCP (`md-dev`, tainted `spp-pool`, namespaces `spp-temporal`/`spp-factory`/`spp-platform`, self-hosted Temporal namespaces `factory` and `platform`) and GCP 2.0 target architecture in `us-east1` |
| **5. Automation** | `adr/automation/` | `ADR-AUT-` | Temporal workflows (`req-*`, `apr-*`, `su-gcp-*`, `drift-*`) and deterministic Kubernetes Job Terraform execution (`tf-<phase>-<20hex>` in `spp-platform`, state in `gs://microdrive-dev-spp-tfstate`), Day-2 operations & alert-only drift detection, and software factory ADR flow across the 10 role skills |

## 3. Authoring & Linting Rules

1. Copy [`../templates/adr-template.md`](../templates/adr-template.md) into the appropriate level folder (`global/`, `business-process/`, `endpoint-service/`, `per-cloud/gcp/`, or `automation/`).
2. Populate all required metadata lines (`ADR ID`, `Level`, `Status`, `Owner` with `Shared Mailbox:` and `Named Owner:`, `Signers`, `Affected Repos`, `Last Updated`) and required sections (`## Goal`, `## Context`, `## Decision`, `## Requirements`, `## Guardrails`, `## Consequences`, `## Acceptance Criteria`, `## Success Criteria`, `## Affected Repos`, `## Open Questions`, `## Related ADRs`).
3. Validate against the factory ADR linter:
   ```bash
   python3 <path-to-spp-factory-foundation>/gates/scripts/lint_adrs.py adr
   ```
